# 企业微信会议接入可行性调研

## 结论

功能可行，建议优先集成企业微信团队维护的官方
[`wecom-cli`](https://github.com/WecomTeam/wecom-cli)，不要读取企业微信本地数据库、抓包或自动操作客户端界面。

仅仅在电脑上登录企业微信并不足以读取会议。用户仍需在 DailyReport 中主动开启该功能，并完成一次企业微信扫码授权。企业权限策略可能要求管理员批准。

## 当前实现状态

第一阶段已经实现：设置页启用/禁用、CLI 路径与同步间隔、自动授权检测与 Bot ID 展示、手动同步、列表完整分页、详情每批最多 10 条、只导入实际入退会记录、稳定外部 ID 去重、最近 7 天自动补同步、Meeting 分类、严格大于空闲阈值的低优先级合并，以及日报模板输出。CLI 缺失、未授权、超时或返回格式异常都会保留原时间线并在设置页显示明确状态。

暂未实现：进行中会议的实时识别、隐藏会议主题隐私选项，以及官方返回多次入退会明细时的分段导入。目前官方 CLI 的详情字段只提供最早入会和最晚离会时间，因此多次进出暂按一个候选区间处理；低优先级合并仍保证不会覆盖期间检测到的其他活动。

## 推荐数据链路

1. 设置页提供“连接企业微信会议”，默认关闭。
2. 设置页显示安装与扫码授权命令；同步未授权时展示 CLI 返回的错误。
3. 启动后、手动触发及定时间隔调用 `wecom-cli meeting list`，完整处理游标分页并回看最近 7 天。
4. 将返回的 `created_meetings` 和 `attended_meetings` 合并、去重。
5. 每批最多 10 个会议 ID 调用 `wecom-cli meeting get` 获取详情。
6. 对已经结束的会议，优先使用 `current_user_enter_time` 和
   `current_user_quit_time` 作为本人真实参会区间；不能只使用预约时间。
7. 将区间裁剪到报告范围，合并重叠区间，然后按“空闲占比”规则决定是否生成会议活动。

官方 CLI 的[会议列表说明](https://github.com/WecomTeam/wecom-cli/blob/main/skills/wecomcli-meeting/references/meeting-list.md)
明确区分当前用户创建和参加的会议，并提供本人入会/离会时间、是否已入会和参会时长等字段。

## 对现有时间统计的影响

会议需要成为一个独立的 `Meeting` 分类，但它是低优先级的空闲补全信息，不能覆盖已经检测到的真实活动：

- 先计算候选会议区间内的已监控时长和 `UserIdle` 时长；程序未运行造成的数据缺口不算空闲；
- `空闲占比 = 空闲秒数 / 有效监控秒数`，只有严格大于 30% 时才启用会议标记；
- 达到阈值后，只把会议区间内原本属于空闲的片段改为 `Meeting`，编码、文档、浏览、构建和娱乐等真实活动全部保留原分类；
- 空闲占比不超过 30% 时不生成会议时长，时间线保持原始活动分类；
- 会议分类计入有效工作时间，但只计算被会议填补的空闲片段，不使用整个预约时长；
- 当前 CLI 只返回最早入会和最晚离会时间；后续若官方开放分段明细，应分别计算每段空闲占比；
- 只有预约、没有本人入会证据的会议默认不自动计时，避免把延期或取消的会议误判成工作。

例如一场 60 分钟的会议中，检测到 25 分钟空闲和 35 分钟编码：空闲占比约为 41.7%，因此 25 分钟标记为会议，35 分钟仍保持编码；若只有 10 分钟空闲，则整段保持原始分类。

腾讯会议的官方接口也能查询用户创建或参加过的已结束会议，参见
[查询用户已结束会议列表](https://cloud.tencent.com/document/product/1095/53805)。
对于具备相应权限的会议，[参会成员明细](https://cloud.tencent.com/document/product/1095/42701)
还会返回每次入会和离会时间，但普通参会者不一定拥有查询整场成员明细的权限。

## 可靠性分级

1. **官方 CLI + 实际入退会时间：推荐。** 可覆盖电脑、手机等终端参加的企微会议，适合会后生成报告；仍需通过 30% 空闲阈值后才补全空闲片段。
2. **会议预约时间：仅作候选。** 用户可能被邀请但没有参加、会议可能延期，不能直接算作工作时长。
3. **本机进程与音频流：可作实时补充。** 能识别电脑正在使用企业微信/腾讯会议通话，但无法覆盖手机参会和线下会议。
4. **读取本地数据库或 UI 自动化：不建议。** 客户端升级后容易失效，也存在隐私、合规和账号安全风险。

## 限制与隐私设计

- 正在进行中的会议可能尚无完整离会时间；当天报告应允许会后重新同步和修正。
- 授权失效或网络失败时，应保留原时间线并明确提示“会议数据未同步”，不能猜测会议时长。
- 默认只保存会议主题、本人入退会时间和来源 ID；参会人、纪要、转写和录制地址默认不采集。
- 提供“隐藏会议主题，仅显示会议”隐私选项。
- 使用会议 ID + 子会议 ID + 入会时间作为幂等键，避免重复导入。
- 官方 CLI 仍处在较快迭代阶段，正式集成时应固定并验证兼容版本，同时保留直接调用官方 API 的替换层。

## 后续实施顺序

1. 增加“隐藏会议主题，仅显示会议”隐私开关。
2. 在报告生成动作前等待一次有上限的同步，减少刚结束会议的延迟。
3. 增加跨天会议、周期会议、多次进出、监控数据缺口和离线重试测试。
4. 官方提供分段入退会数据后，将一个候选区间升级为多段精确区间。
5. 最后再考虑本机音频/进程检测，用于补齐进行中的会议。
